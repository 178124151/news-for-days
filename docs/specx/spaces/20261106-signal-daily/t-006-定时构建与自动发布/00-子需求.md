## t-006: 定时构建与自动发布（GitHub Pages）

### 来源
> 摘录自 `raws/P001-原始需求.md`

「每天定时获取内容托管在静态网页上」+ 用户确认零成本、无人工。

### 范围

包含：
- GitHub Actions 工作流：`schedule`（每日 22:30 UTC / 06:30 CST）+ `workflow_dispatch`
- 步骤：安装依赖 → 采集 → 加工 → 校验 → 构建 → 提交内容 → 上传 Pages artifact → 部署
- 使用官方 `actions/configure-pages`、`actions/upload-pages-artifact`、`actions/deploy-pages`
- 权限：`contents: write`（提交内容）、`pages: write`、`id-token: write`
- 并发锁，避免两次运行重叠
- 依赖缓存（pnpm、Pagefind）
- 失败通知：GitHub Issue / GitHub 自带失败通知
- 内容提交到 `main`，保留完整历史；提交信息带 `[skip ci]` 防止循环
- 工作流可本地复现（`pnpm pipeline && pnpm build`）

不包含：
- 页面实现（t-005）
- 域名与监控（t-007）
- 付费 CI / 付费部署

### 依赖
- 依赖：t-001, t-004
- 被依赖：t-007

### 关键约束
- 公开仓库：GitHub Actions 标准 runner 免费；Pages 免费
- 端到端 < 20 分钟（Pages 部署本身有 10 分钟超时）
- GitHub cron 有 5–30 分钟漂移；个人使用可接受
- 部署失败时线上保留上一成功版本，不发布空站
- 连续 60 天无仓库活动会导致定时工作流被禁用；每日内容提交天然保持活跃
