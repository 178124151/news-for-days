## 1. 策略选择

> 核心复杂度在哪里？

本项目的主要复杂度在**数据与内容管线**：多源采集、规范化、去重聚类、AI 加工、数据契约、定时构建。页面展示是管线的消费端，交互复杂度低。

因此选择 **策略 A：抽象层优先**，辅以按页面/运维模块拆分的实现层。

## 2. 抽象层与实现层划分

| 层 | 子需求 | 说明 |
|----|--------|------|
| 抽象层 | t-001 内容源接入与采集 | 数据从哪来、如何稳定取到 |
| 抽象层 | t-002 内容规范化与去重 | 数据长什么样、如何判定同一条 |
| 抽象层 | t-003 AI 加工与内容分级 | 摘要、标签、分类、重要性规则 |
| 抽象层 | t-004 内容存储与构建数据契约 | 落盘格式、版本、构建输入输出 |
| 实现层 | t-005 静态站点与信息架构 | 首页、分类、详情、日报、搜索 |
| 实现层 | t-006 定时构建与自动发布 | GitHub Actions / Cron + 部署 |
| 实现层 | t-007 托管、访问与可观测性 | GitHub Pages、免费域名、大陆兜底、健康报告 |
| 实现层 | t-008 合规、版权与自动质检 | 授权边界、自动质检、免责声明、下架流程 |
